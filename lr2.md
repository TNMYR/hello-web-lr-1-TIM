# Лабораторная работа №2. Интерактивный Frontend и State-Driven SPA

**Курс:** Веб-программирование

**Тема лекции-основы:** JavaScript, DOM, обработка событий, формы и Web Storage API  

**Формат результата:** Модернизированный проект из Лабораторной работы №1 с добавлением JavaScript-логики (одностраничное интерактивное приложение)

---

## 1. Цель работы

Превратить статический HTML/CSS-макет, разработанный в рамках Лабораторной работы №1, в динамическое интерактивное веб-приложение (Single Page Application — SPA). 

В ходе работы нужно продемонстрировать умение:
1. Работать с DOM-деревом (поиск, создание, изменение и удаление элементов).
2. Обрабатывать пользовательские события и использовать паттерн **делегирования событий** (`Event Delegation`).
3. Реализовывать клиентскую валидацию форм с помощью **Constraint Validation API**.
4. Управлять состоянием приложения в архитектуре **State-Driven UI** (`UI = render(State)`).
5. Обеспечивать постоянство данных (Data Persistence) с помощью **Web Storage API (`localStorage`)**.

## 3. Обязательный технический функционал

Независимо от выбранной темы, необходимо реализовать в своем проекте минимум **8 ключевых возможностей**:

### 3.1. Динамический поиск (Search)
- Текстовое поле ввода (`<input type="text">`) для поиска элементов по названию или тексту.
- Поиск должен срабатывать в реальном времени (по событию `input`) или по нажатию клавиши/кнопки.
- Регистр символов при поиске не должен иметь значения (`toLowerCase()`).

### 3.2. Фильтрация (Filtering)
- Выпадающий список (`<select>`) или группа кнопок/чекбоксов для фильтрации по категориям, тегам или статусам.
- Обязательно наличие пункта **«Все категории»** (сброс фильтра).

### 3.3. Сортировка (Sorting)
- Выпадающий список (`<select>`) с выбором критерия сортировки (минимум 2 направления, например):
  - По алфавиту (А–Я / Я–А);
  - По числовому значению (сначала дешевле / сначала дороже, по дате, по рейтингу).
- Использование иммутабельной сортировки в JavaScript без разрушения исходного массива данных.

### 3.4. Модальное окно (Modal Dialog)
- Всплывающее модальное окно для добавления нового элемента в систему.
- Открытие окна по кнопке «Добавить элемент» / «Создать запись».
- Закрытие окна по кнопке-крестику (`×`), кнопке «Отмена», нажатию клавиши `Escape` или клику по подложке (backdrop).

### 3.5. Форма добавления и клиентская валидация
- Форма внутри модального окна для ввода данных новой сущности.
- **Обязательные требования к валидации:**
  - Использование HTML5-атрибутов (`required`, `minlength`, `min`, `max` и т.д.).
  - Перехват отправки формы через `e.preventDefault()`.
  - Проверка валидности полей через JavaScript (`input.validity`).
  - Вывод понятных текстовых сообщений об ошибках под невалидными полями при попытке отправки.

### 3.6. Удаление элемента (Event Delegation)
- Кнопка «Удалить» на каждой карточке/строке элемента.
- Обработка удаления **строго через делегирование событий** (один слушатель событий `click` на общем родительском контейнере с использованием `e.target.closest()`).

### 3.7. Сохранение данных в localStorage
- Сохранение текущего списка элементов в `localStorage` при любом изменении (добавление, удаление).
- Сериализация и десериализация данных через `JSON.stringify()` и `JSON.parse()`.
- При перезагрузке страницы данные должны считываться из `localStorage`. Если хранилище пустое — должны загружаться демонстрационные начальные данные (Default State).

### 3.8. Архитектурный подход State-Driven UI
- Данные приложения хранятся в едином объекте состояния `state`:
  ```javascript
  const state = {
      items: [],          // Массив элементов
      searchQuery: '',    // Строка поиска
      selectedCategory: 'all', // Выбранный фильтр
      sortBy: 'name-asc'  // Режим сортировки
  };
  ```
- Изменение интерфейса происходит путем перерисовки (`render()`) на основе актуального `state`.

## 4. Требования к коду и структуре проекта

1. **Чистота и безопасность кода:**
   - Для вставки текстовых данных от пользователя использовать **`textContent`** (избегать `innerHTML` для пользовательского ввода во избежание XSS-уязвимостей).
   - Запрещено использовать устаревший синтаксис `var` (только `const` и `let`).
   - Запрещено использовать нестрогое сравнение `==` (только строгое `===`).
2. **Семантика и стили:**
   - Веб-страница должна сохранять аккуратный адаптивный внешний вид на белом/светлом фоне.
   - Отсутствие горизонтальной прокрутки на мобильных устройствах.
3. **Отсутствие сторонних тяжелых библиотек:**
   - Весь функционал DOM и логика должны быть написаны на **чистом JavaScript (Vanilla JS)** без использования jQuery или сторонних SPA-фреймворков.
